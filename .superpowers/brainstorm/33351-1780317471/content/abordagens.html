Decomposição: services/storage.ts

3 abordagens — escolha a que faz mais sentido pro projeto

A

Por Entidade Recomendado

1 entidade = 1 arquivo. Cada arquivo tem acesso ao cliente Supabase e exporta só suas operações. index.ts re-exporta tudo — nenhum import quebra. 

services/storage/
├── index.ts           (re-export barrel)
├── types.ts           (tipos compartilhados)
├── dossiers.ts        (CRUD 4 ops)
├── userContext.ts     (4 ops)
├── favorites.ts       (3 ops)
├── radar.ts           (4 ops)
├── sharedDossiers.ts  (2 ops)
├── extractCache.ts    (IDB, 2 ops)
└── audit.ts           (1 op)

Vantagens

  • Cada arquivo <80 linhas
  • Testável isoladamente
  • Segue padrão services/gemini/ (12 arquivos)
  • Fácil de achar: "onde está o CRUD de dossiês?" → dossiers.ts

Desvantagens

  • 9 arquivos (muitos imports pra editar)
  • Tipos compartilhados precisam de types.ts
B

Por Backend de Persistência

Agrupa por tecnologia de storage: Supabase, IndexedDB, localStorage. Menos arquivos, mas cada um ainda tem múltiplas entidades. 

services/storage/
├── index.ts           (re-export)
├── supabase.ts        (dossiês + favorites + radar + shared + user + audit — ~350 linhas)
├── extractCache.ts    (IDB — ~40 linhas)
└── localConfig.ts     (localStorage operator — ~20 linhas)

Vantagens

  • Só 4 arquivos
  • Separação clara por tecnologia

Desvantagens

  • supabase.ts ainda teria 350+ linhas com 6 entidades
  • Não resolve o problema de god module completamente
  • Mesmo problema de hoje, só que menor
C

Híbrido: Entidades Grandes + Agrupados

Entidades com mais operações viram arquivos próprios. As menores (audit, extractCache, sharedDossiers) ficam agrupadas. 

services/storage/
├── index.ts           (re-export)
├── types.ts
├── dossiers.ts        (4 ops, ~80 linhas)
├── userContext.ts     (4 ops, ~60 linhas)
├── radar.ts           (4 ops, ~70 linhas)
├── misc.ts            (favorites 3 + shared 2 + audit 1 + extractCache 2 — ~160 linhas)

Vantagens

  • Meio termo: 6 arquivos
  • Entidades complexas isoladas

Desvantagens

  • misc.ts é um mini god module
  • Critério subjetivo do que agrupar
  • Cresce desorganizado com o tempo
